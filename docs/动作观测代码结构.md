# 动作观测代码结构

动作代码按“规则、目录、运行时装配、状态机”分层。新增观测点时不得在 Demo 中直接
硬编码步骤列表。

## 目录职责

- `src/observations/`：按业务域提供稳定的动作类导入。
- `src/observations/_rules.py`：当前规则实现的内部集合，不作为新代码的导入入口。
- `src/observation_catalog.py`：动作注册表，统一处理模型类别、摄像机角色和可选模块。
- `src/sop_config.py`：加载并校验 SOP YAML，按当前能力裁剪节点。
- `src/sop_runtime.py`：从配置和当前动作 ID 集合创建状态机。
- `src/sop_state_machine.py`：只处理事件、顺序、超时、重试和人工复核。
- `src/action_observations.py`：旧导入路径的兼容层。

业务域模块：

- `layout.py`：品茗杯和茶盘布局；
- `warm_clean.py`：温杯洁具顺序；
- `preparation.py`：取茶和双手托举；
- `smell.py`：开盖闻香；
- `brewing.py`：盖合、出汤和等待时间；
- `accessory.py`：手部饰品。

## 新增动作步骤

1. 在对应业务域实现或导出观测器，保持统一 `ObservationSnapshot` 和
   `ObservationEvent` 接口。
2. 在 `observation_catalog.py` 注册类别条件、机位和构造函数。
3. 在 `config/sop_red_tea_v1.yaml` 增加或启用 `runtime_nodes` 节点。
4. 在能力矩阵中同步状态、数据缺口和正式评分可用性。
5. 增加观测器单元测试和完整状态机集成测试。

实时 Demo 和双机位 Demo 均从同一 YAML 装配状态机，不再各自维护步骤副本。
