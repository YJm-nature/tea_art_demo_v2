# 茶艺红茶 SOP 视觉检测完整项目设计与迭代方案

版本：2026-07-28

依据：`0611修订茶艺红茶操作流程需求确认表0602.docx` 与 `tea_art_demo_v2`

GTX 1060 6GB 的实际数据审核、补采、发布和训练命令见 [数据集重建与6GB训练操作手册.md](数据集重建与6GB训练操作手册.md)。

## 1. 结论

本项目不应被设计成“一个模型直接识别六个步骤”。可落地方案是以多机位视频为输入，以物体检测/跟踪为基础，组合手部与人体关键点、物体关键点、动作事件、液体/污渍分割、仪表 OCR，再由事件总线和有限状态机完成 SOP 时序判定，最后由独立规则引擎生成可追溯评分。

每一个得分必须能回溯到以下证据：摄像机、时间段、目标轨迹、数值/动作结果、置信度、规则版本和模型版本。低置信度结果应进入人工复核，不应静默判错。

当前 demo 可以作为“物体感知与跟踪层”的原型，但还不是步骤一的完整验收实现，更不是完整 SOP。最先要解决的是独立测试集、需求口径、摄像机标定和事件数据结构，而不是继续在三个视频的相邻帧上堆训练轮次。

## 2. 需求基线与待确认项

需求定义六步：备具布席、温杯洁具、投茶准备、投茶闻香、注水冲泡、分茶与奉茶。

需求表存在以下验收歧义，应形成教师签字的“评分规则 v1.0”后冻结：

1. 各步骤注明观测点为 10+7+6+9+7+6=45 个，但汇总写 19 个；“物品判断6个”后又列出 13 种物品。
2. 文档在“总分为100分，由”处结束，没有给出六类评分维度的权重。
3. 红茶温度同时出现 95-100℃和 90-100℃。
4. 投茶量同时出现 3g、3±0.3g和3-5g。
5. 品茗杯布局同时允许一字形和品字形，但没有说明人数与布局的对应关系。
6. “只要有一滴水就扣分”缺少最小可见面积、持续时间和桌面反光排除规则。
7. 1.5 米操作半径无法从未标定的单目像素坐标直接判断。

建议教师逐项确认：必选/可选、分值、容差、是否允许重做、步骤跳过规则、严重违规上限、人工复核条件。规则配置需版本化，历史报告不能随新规则改变。

## 3. 当前 demo 与数据审计

### 3.1 已有能力

- YOLO 茶具检测、ByteTrack 跟踪、跨帧记忆；
- 9 类模型：盖碗、公道杯、品茗杯、茶荷、茶巾、茶夹、茶拨、茶叶罐、建水；
- MediaPipe 手部/姿态接口与遮挡启发式；
- 单帧布局提示、OpenCV 实时展示；
- 观测点类框架，但主流程目前只路由步骤一物品观测点。

步骤一需求的 10 个必备品中，现模型只覆盖 8 个；茶盘和烧水壶不可识别。茶叶罐属于后续步骤物品，不能补偿步骤一缺失。因此，即使当前画面得分为 100，可观测需求覆盖率也只有 80%。

### 3.2 数据集实测

`final_tea9_dataset_20260723`：

| 指标 | 结果 |
|---|---:|
| 图片 | 848（train 678 / val 170） |
| 实例 | 8229（train 6588 / val 1641） |
| 来源 | office 500 / original 298 / focus 50 |
| 标注来源 | office_auto 450 / office_manual 50 / original 298 / focus_manual 50 |
| 最大/最小类实例比 | 2.64:1 |
| 相邻帧跨 train/val | 545 对（帧号间隔不超过2） |

品茗杯 1896 个实例，而最少的茶巾为 718 个；这部分差异主要由品茗杯天然多实例造成，评估时应同时看“包含该类的图片数”，不能只按框数盲目过采样。

训练日志最后阶段约为 `mAP50=0.982`、`mAP50-95=0.839`。由于三个来源都同时进入 train 和 val，且存在大量相邻帧泄漏，该数值不能作为新场景验收指标。

## 4. 总体架构

```text
顶部全景 + 侧面动作 + 仪表近景（可选）
                 |
       时间同步、标定、ROI与隐私处理
                 |
  物体检测/跟踪 | 手/人体姿态 | OCR | 分割 | 物体关键点
                 |
       统一事件层（对象-动作-关系-数值-时间）
                 |
       SOP有限状态机 + 规则引擎 + 置信度融合
                 |
       实时提示 / 证据回放 / 报告 / 人工复核
```

### 4.1 采集层

- 顶部或高位斜俯相机：器具、桌面、杯序、溅水、布局；建议 4K、25/30 FPS、固定焦距和曝光。
- 正侧面相机：双手托举、齐胸展示、闻香、倾角、鞠躬；1080p 以上。
- 仪表近景：水壶温度和电子秤；如果业务允许，优先读取设备数字接口，其可靠性高于远距离 OCR。
- 三机位用同一时钟或开场拍手/闪光做同步；保存标定参数、ROI、相机编号。
- 桌面铺设已知尺寸标定板或四角标记，用单应性把像素转换到桌面厘米坐标，才能判断操作半径和相对距离。

### 4.2 感知与事件层

统一事件建议采用如下结构：

```json
{
  "event_id": "evt-...",
  "type": "pour_into",
  "subject_track": "kettle-3",
  "object_track": "gaiwan-1",
  "start_ms": 18230,
  "end_ms": 21480,
  "camera_ids": ["top", "side"],
  "confidence": 0.91,
  "evidence": [{"frame": 552, "bbox": [0, 0, 0, 0]}],
  "model_version": "pour-v1.2"
}
```

事件层隔离模型与业务规则。后续更换 YOLO、姿态或动作模型时，SOP 状态机和评分报告无需重写。

### 4.3 SOP 状态机

以“观测点事件”驱动状态，而不是用当前帧类别猜步骤。状态机应支持：允许的前置步骤、超时、可重试、跳步、并行动作、严重违规和人工确认。步骤完成后保存证据窗口，不仅保存最终布尔值。

## 5. 六步实现拆解

| 步骤 | 核心观测 | 推荐实现 |
|---|---|---|
| 1 备具布席 | 10个必备器具、数量、布局、操作半径 | 目标检测+跟踪；桌面标定；对象关系图；稳定存在窗口 |
| 2 温杯洁具 | 水壶温度、盖碗→公道杯→品茗杯、废水入建水、无溅水 | OCR/设备接口；壶与器具交互事件；时序状态机；桌面变化/液滴分割 |
| 3 投茶准备 | 茶叶罐/茶荷/秤、3g、双手托举 | 物体检测；秤屏 OCR；双手-茶荷空间关系；动作持续时间 |
| 4 投茶闻香 | 茶荷展示5-10秒、投茶、轻摇、闻香、角度 | 侧面姿态+物体关键点；时序动作模型；鼻-盖碗距离；茶叶洒落分割 |
| 5 注水冲泡 | 旋冲、水位、浸没、等待8-12秒、倒入公道杯、无溅出/茶渣 | 壶嘴轨迹；液流/液面分割；盖合/出汤事件计时；桌面前后差分与分割 |
| 6 分茶奉茶 | 左到右或右到左、七分满、杯布局、双手托盘、鞠躬 | 多杯轨迹和倒茶事件序列；侧视液面；布局图匹配；双手接触+人体姿态 |

角度判断不要仅用人体骨架近似器具角度。茶荷、盖碗应标注器具关键点或姿态，经过相机标定后计算；遮挡严重时采用侧面机位融合。

## 6. 评分设计

评分分三层：

1. 观测点结果：`pass / fail / uncertain / not_observable`，包含测量值、容差和证据。
2. 步骤分：按教师配置的观测点权重汇总。`uncertain` 不应直接算错，进入人工复核。
3. 总分：六步骤权重、顺序扣分和安全违规封顶规则。安全类宜采用扣分/封顶，不宜被其它高分抵消。

当前 demo 步骤一暂定口径：必备物存在完整度 80%、数量正确性 10%、布局启发式 10%。检测稳定性只作为证据可靠度，不参与学员得分；茶盘、烧水壶等未覆盖项通过需求覆盖率披露。该公式是工程占位，不是已确认验收规则。

完整系统建议由教师配置每个观测点的 `weight`、`tolerance`、`critical`、`manual_review_threshold`。最终报告同时给出机器原始分、人工修订分和修订理由。

## 7. 数据集优化方案

### 7.1 立即修正

1. 不再按帧随机拆分。以“参与者+场地+日期+机位+完整录制 session”为 group，整个 group 只能属于 train、val 或 test。
2. 保留一个从未参与调参的独立 test：至少包含新参与者、新器具套装和新光照。三场景数据过少时使用 leave-one-scene-out 三折评估。
3. 对 450 张自动标注进行抽样复核；每类至少抽 50 个框，统计漏标率、错类率和 IoU，通过质量门槛后才能进入 gold 数据。
4. 使用感知哈希/SSIM 对抽帧去重。静态备具建议相邻样本至少相隔 1-2 秒，并优先保留物体状态发生变化的帧。
5. 将数据版本、来源视频、帧时间、人物、器具套装、场地、标注方式写入 manifest，不依赖文件名猜测。

### 7.2 采集矩阵

第一阶段目标不是大量帧，而是覆盖组合：建议至少 20-30 名操作者、5 套器具、3 个场地、3 种光照、左右手、正确/错误/纠正三类流程。每个关键动作至少采集 100 个独立动作片段，安全违规和少见错误需定向补采。

步骤一每类建议先达到 300-500 张“独立场景图片”，同时加入 20%-30% hard negatives：相似白瓷、手部遮挡、反光、只露局部、错误数量、错误布局、缺失单件。类别平衡以“独立 session 数”和“含该类图片数”为主，不追求每类框数完全相等。

### 7.3 标注层级

- 物体：框、遮挡率、截断、track ID；细长茶夹/茶拨可考虑实例分割。
- 动作：起止时间、主体手、目标器具、正确/错误标签。
- 关系：手持、靠近、倒入、位于茶盘内、杯的左右序号。
- 结果：液滴/茶渣 mask、液面、OCR 数值、布局类型。
- SOP：步骤起止、跳步、重做、违规、教师总评。

标注规范先做 50 段双人复标，计算类别一致率、框 IoU、动作边界偏差；争议样本经教师仲裁后再扩标。

### 7.4 主动学习闭环

每轮部署收集低置信度、模型分歧、误报高发、人工改分样本；聚类去重后优先标注。每次训练固定独立 test，输出按场景/人物/器具的切片指标，禁止只报告总体 mAP。

仓库已提供：

```powershell
python scripts/audit_dataset.py dataset/final_tea9_dataset_20260723
python scripts/group_split_dataset.py dataset/final_tea9_dataset_20260723 dataset/tea9_scene_holdout --val-sources office
```

第二个命令只写入新目录，拒绝覆盖非空目录。由于目前只有三个来源，应分别将 `office`、`original`、`focus` 作为验证来源跑三次，而不是只选一个结果最好看的划分。

## 8. 验收指标

- 物体：独立 test 上逐类 Precision、Recall、AP50-95；必备品优先看 Recall，建议每类 Recall≥0.90。
- 跟踪：IDF1/HOTA，以及关键器具 ID switch。
- 动作事件：逐事件 Precision/Recall/F1、时间边界误差、顺序识别准确率。
- OCR：温度/克数 MAE 与落入业务容差的准确率。
- 安全/溅水：Recall 优先，并报告每小时误报数。
- SOP：步骤完成 F1、完整顺序准确率、跳步检出率、端到端报告生成率。
- 评分：与至少两名教师盲评比较 MAE、相关系数/ICC；机器与教师差异超过阈值自动复核。
- 工程：目标硬件实时 FPS、P95 延迟、掉帧率、连续运行稳定性。

指标门槛必须按场景切片满足，不能用优势场景的平均值掩盖弱场景。

## 9. 迭代路线

### M0：需求与采集基线（1-2周）

冻结评分规则 v1.0、机位、标定方式、事件 schema、数据 manifest 和验收集；教师标注 20-30 段完整正确/错误流程作为黄金样本。

### M1：步骤一可验收 demo（2-4周）

补齐茶盘、烧水壶，建立独立场景 test；实现稳定窗口、数量、桌面坐标/操作半径、布局规则、证据报告和人工复核。当前仓库改造是这一阶段的工程起点。

### M2：温杯与投茶（4-6周）

先打通可量化的温度 OCR、投茶重量 OCR、倒水对象时序和双手托举；形成统一事件总线和步骤状态机。

### M3：闻香与冲泡（6-10周）

采集动作片段，训练器具关键点/时序动作与液体分割；重点解决遮挡、多机位同步和不确定性复核。

### M4：分茶奉茶与端到端（4-6周）

完成多杯序列、液面、布局、托盘与鞠躬；串联六步，做错误注入、压力测试和教师一致性验收。

## 10. 下一阶段的完成定义

步骤一只有同时满足以下条件才算“完成”，而不是摄像头上能画框：10 个必备品全覆盖；独立场景测试；数量与布局可判；桌面标定后可判断操作范围；连续证据窗口抑制瞬时误报；每项结果可回放；低置信度可复核；评分规则经教师签字；模型、规则、数据版本进入报告。
