## 2. 碗盖与碗身能否区分

可以训练成两个类别，因为标签固定为：

- class 0：盖碗碗身
- class 1：盖碗碗盖

但“标签分开”不等于“模型一定可靠”。本轮训练后必须分别查看碗身和碗盖的 Precision、Recall、mAP，并用实时开盖视频验证连续轨迹。

当前主要风险：

1. 多数图片是盖合状态，碗身和碗盖框重叠。
2. 缺少碗盖完全取下、手持、遮挡、靠近鼻部和重新盖合状态。
3. 白色碗身容易和品茗杯混淆。
4. test 只有 32 张，适合发现明显回退，不能证明广泛泛化。

启用闻香观测前，至少再补 3 个新 session，每个 session 覆盖：盖合、手接触盖、盖分离、盖手持、碗身手持、靠近鼻部、重新盖合，以及“拿品茗杯喝水”等困难负例。建议新增 300-500 张关键帧。

最低启用门槛：碗身和碗盖独立测试 Recall 均不低于 0.85；完整闻香视频 Precision 不低于 0.90、Recall 不低于 0.85。

需求报告中的“手部饰物和指甲”属于安全评分附加项：

- 饰品：MediaPipe 手腕 ROI + 独立 nano 检测器，类别为戒指、手链/手镯、手表。
- 数据：600-1000 张手部 ROI，裸手负样本至少 40%，覆盖反光茶具和亮色衣袖。
- 指甲：建议独立做“长/装饰指甲”二分类或检测，不与饰品三类混在一起；至少 500 张清晰手部 ROI。

## 5. 动作与完整流程视频

器具检测图片不能替代动作视频。动作数据放入 `dataset/action_observations_v1`，按完整连续录制 session 隔离。

优先录制顺序：

1. 开盖闻香专项：正确动作、只开盖不闻、拿杯喝水、鼻部遮挡。
2. 温杯洁具专项：盖碗 -> 公道杯 -> 品茗杯 -> 建水，以及所有错序。
3. 冲泡专项：旋冲、普通直冲、无液流假动作、溅水。
4. 分茶专项：左右两个方向、乱序、漏杯、重复倒同一杯。
5. 奉茶专项：双手端盘、单手端盘、桌面推盘、端盘不鞠躬、只鞠躬。
6. 完整 SOP：至少 30 段完全正确流程，再录制每种关键错误至少 20 段。

只有一个摄像头时可先录制两类 session：

- 斜俯桌面：器具、杯位、倒水目标、液体和溅水。
- 正侧面：托举、倾角、闻香、端盘和鞠躬。

最终同时验收桌面结果和面部/身体动作时，建议增加第二摄像头。单个固定机位很难同时看清杯内液面和鼻部距离。

## 6. 实施顺序

### 阶段 A：现在执行

1. 使用已发布的 645 张原型集完成 3 epoch 冒烟训练。
2. 检查类别映射、显存、损失曲线和碗身/碗盖是否出现在验证结果。
3. 冒烟通过后训练 640/50 epoch 基线。
4. 在独立 focus test 上分别查看 class 0 和 class 1 指标，并用实时视频检查。

### 阶段 B：不等新器具即可做

1. 录制并标注杯位、托举茶荷和开盖闻香动作片段。
2. 补 3 个新场景的碗身/碗盖动作关键帧。
3. 完成 O07、O09、O19 的独立视频验收。
4. 录制手部饰品和指甲 ROI。

### 阶段 C：器具补齐后

1. 补 8 个延期检测类别，不改变已有类别编号。
2. 训练完整 18 类 nano 检测模型。
3. 实现温杯顺序、冲泡、分茶顺序、双手端盘和 OCR。
4. 单独建设液体/溅水/茶渣/液面分割数据集并训练 nano-seg。

### 阶段 D：完整 SOP

1. 每个观测器只发布 `started/completed/failed/uncertain` 事件。
2. `SopStateMachine` 按 O01-O19 配置前置条件、8-12 秒等待、超时和重试。
3. 自由观测模式完成单点验收后，再切换 strict SOP 模式。
4. 最终评分按步骤 40%、物品 30%、时间 10%、安全规范 20% 汇总；未经独立验收的实验观测不计分。

## 7. 当前训练命令

先关闭实时 Demo、浏览器硬件加速和其他占用显存的软件。进入项目目录：

```powershell
cd E:\tea_culture\tea_art_demo_v2
```

只先运行冒烟训练：

```powershell
& "D:\anaconda3\envs\tea-ai-6gb\python.exe" scripts\train_6gb.py `
  --config config\training_gaiwan_prototype_6gb.json `
  smoke dataset\tea_dataset_current10_prototype_20260731\data.yaml `
  --name current10_smoke_20260731
```

完成后先检查 `models/low_vram/current10_smoke_20260731`。不要立即开始正式训练；先确认日志没有类别映射、CUDA、NaN 或标签错误。

冒烟通过后使用：

```powershell
& "D:\anaconda3\envs\tea-ai-6gb\python.exe" scripts\train_6gb.py `
  --config config\training_gaiwan_prototype_6gb.json `
  stage1 dataset\tea_dataset_current10_prototype_20260731\data.yaml `
  --name current10_640_20260731
```

训练工具会按 `batch 4 -> 2 -> 1` 自动处理 6GB 显存不足。现阶段不要做 960 微调，先看 640 模型的碗身/碗盖 Recall。

正式训练完成后的 test 验证命令：

```powershell
& "D:\anaconda3\envs\tea-ai-6gb\python.exe" scripts\train_6gb.py validate `
  dataset\tea_dataset_current10_prototype_20260731\data.yaml `
  models\low_vram\current10_640_20260731\weights\best.pt `
  --split test --imgsz 640
```

验证报告写入 `output/validation_best_test.json`。重点查看 `per_class["0"]` 和 `per_class["1"]`，不能只看整体 mAP。
