# 全量素材数据集重建与无泄漏发布方案

## 当前盘点结果

截至 2026-08-06，`dataset` 下发现 43 个可读视频和 848 张已经修复标注的图片。修复图片实际位于 `tea_dataset_v1_reviewed/pool/images`，对应标签位于 `pool/labels/detect`；`修框后图片` 中的 MakeSense 压缩包保留为原始审核凭证。现有图片与标签文件名可以一一对应，另有一个孤立的历史 `labels.txt`，不应发布。

六个最新完整流程视频位于 `tea_sop_side_transition_v1/正面完整流程视频`。它们属于同一场景和连续拍摄批次，当前全部归为 `new_front_full_202608`，不能把其中一部分随机放进训练、验证和测试。

自动清单输出：

- `dataset/tea_sop_front_v1/manifests/all_materials.csv`
- `dataset/tea_sop_front_v1/manifests/source_groups.csv`
- `dataset/tea_sop_front_v1/manifests/quality_report.json`

清单工具不会移动、覆盖或删除任何原始素材。视频指纹使用大小加首尾块，避免每次扫描完整读取大视频；视频还记录分辨率、帧率、时长和少量清晰度抽样值。

旧修复检测标签目前的实例数为：盖碗碗身 772、盖碗碗盖 752、公道杯 792、品茗杯 1904、茶荷 811、茶巾 777、茶夹 832、茶拨 801、建水 748、茶叶罐 774。茶盘只有 2 个实例，烧水壶、电子秤、显示屏、温度计、计时器和茶则目前为 0；这些类别不能仅靠旧图片训练，必须在对应实物和正面机位素材补齐后再激活。

848 张旧修复图片没有缺失标签、孤立标签或完全相同的重复文件。近似重复仍需在候选发布阶段按 session 和感知哈希继续筛选。

## 数据分层

原始素材永远留在原位置；新版目录只保存索引、候选帧和发布副本：

```text
dataset/tea_sop_front_v1/
  manifests/
    all_materials.csv          # 全量来源清单
    source_groups.csv          # session 与候选 split
    frame_candidates.csv       # 抽帧来源、帧号、清晰度、审核状态
    action_segments.jsonl      # 动作起止时间，不把动作当 YOLO 类别
  derived/
    detection_pool/full_frames/<session>/<module>/
    pose_pool/<session>/<target>/
    ocr_pool/<session>/<temperature|weight>/
    action_clips/<session>/<action>/<positive|error|hard_negative>/
  annotations/
    detection_yolo18/          # 主器具 YOLOv8n 标签
    pose_yolo/                 # 壶嘴/中心/手柄等关键点标签
    ocr/                       # 显示屏 ROI 与真实数值
    actions/                   # JSONL 时间段和审核结果
  releases/
    detection/{train,val,test}/
    pose/{train,val,test}/
    ocr/{temperature,weight}/{train,val,test}/
    action/                    # 只保存审核通过的事件片段/元数据
```

`derived` 是候选池，不能直接训练；只有 `review_status=approved` 且通过 session 审核的素材才允许进入 `releases`。

## 当前来源分组

清单会自动生成以下类型：

- `legacy_reviewed_*`：848 张旧人工修复图片，作为检测训练候选，默认只能进 train candidate。
- `legacy_utensils_202606`：单件、组合、遮挡、空桌等旧器具视频。
- `legacy_actions_202606`：托举茶荷和杯位布局正负例。
- `legacy_inbox_202606`：早期多场景/完整流程视频，先审核机位后使用。
- `legacy_root_*`：项目根目录历史视频，必须人工确认内容和视角。
- `new_front_full_202608`：最新六段正面完整流程，同一 session，先作为整体候选。

不要按文件名或图片名随机切分。任何来自同一连续视频、同一操作者同一场景的图片必须保持在一个 session 内。

## 抽帧原则

运行：

```powershell
cd E:\tea_culture\tea_art_demo_v2
python scripts\build_material_manifest.py
python scripts\extract_balanced_candidates.py --module utensil_static --per-video 16 --module-limit utensil_static=180
python scripts\extract_balanced_candidates.py --module full_sop --per-video 12 --module-limit full_sop=120
```

候选抽帧器会：

1. 每个视频单独限额，避免长完整流程视频淹没静态器具数据。
2. 跳过低 Laplacian 清晰度帧，默认阈值为 35，可按实际画面调整。
3. 使用 dHash 距离去掉相邻近重复画面。
4. 在文件名和 `frame_candidates.csv` 中保留原视频、session、模块和帧号。
5. 只生成候选图片，不自动生成 YOLO 标签，也不自动发布 split。

视频较长时按模块分批运行，不要一次处理全部视频。动作数据应保留完整原视频和动作起止时间；检测图片只需保留动作前、接触、拿起、遮挡、最大倾斜、恢复等高价值帧。

短动作（尤其是闻香）不要依赖完整流程的均匀抽帧。先在 `manifests/action_segments_review.csv` 填写时间段，例如：

```text
source_relative_path,session_id,action_id,variant,start_s,end_s,notes
tea_sop_side_transition_v1/正面完整流程视频/1.mp4,new_front_full_202608,open_lid_smell,positive,123.4,128.8,开盖靠近鼻部并保持
```

然后运行：

```powershell
python scripts\extract_action_segment_frames.py `
  --fps-sample 5 `
  --max-frames 24
```

结果写入 `derived/action_pool/<session>/<action>/<variant>`，同时记录到 `action_frame_candidates.csv`。该池用于动作证据和关键帧审核，不能把动作名称直接加入器具 YOLO 类别。

## 发布 split 的规则

正式发布前先编辑 `source_groups.csv`，为每个 session 填写操作者、拍摄日期、光照、机位和 `review_status=approved`。建议至少准备：

- train：至少 5 个独立 session，包含旧修复图片和已审核的旧/新训练素材；
- val：至少 1 个未进入 train 的完整 session；
- test：至少 1 个全新操作者或全新拍摄日的完整 session，锁定后不再用于调参。

当前素材可以建立 prototype，但不能把同一批六段新视频拆成 train/val/test 后宣称正式指标。若暂时只有这些来源，应明确报告为 `prototype validation`，并补拍一个独立 test session。

检测、关键点、OCR 和动作事件分别发布和评估：

- 检测：所有可见茶具都必须标注，不能因为静止就删除；通过 YOLOv8n 640 基线后，再对碗盖、碗身、茶夹、茶拨做 960 微调。
- 关键点：只标注壶嘴/中心/手柄、盖碗沿等几何点，不把“倾斜角度”作为 YOLO 类别。
- OCR：只保留清晰显示屏 ROI 和真实读数；同一视频的相邻读数不能跨 split。
- 动作：使用 JSONL 起止时间、正例/错误/困难负例；由器具框、Pose、手部、跟踪和状态机判断。

## 与目标能力的对应关系

- 茶具识别：`utensil_static`、`utensil_grouped`、`occlusion_handheld`、848 张修复图片。
- 温杯洁具：`warm_clean` 动作时间段 + 盖碗、公道杯、品茗杯、建水器具框，按交互顺序判定。
- 双手托举茶荷：`hold_lotus` 正例、单手/同侧/短暂经过负例，使用 Hands + 茶荷框 + 离桌规则。
- 赏茶闻香：开盖、靠近鼻部、保持、复盖四阶段；使用碗盖/碗身框和 Pose 鼻部点。
- 投茶入盖碗：茶荷/茶拨靠近盖碗上方并发生倾斜或拨入轨迹；不声称检测到茶叶实际掉落。
- 注水：水壶倾斜、壶嘴进入盖碗扩展区域并保持；关键点计算方向。
- 冲泡时间：盖合事件到盖碗开始出汤的单调时间差，8--12 秒合格。
- 出汤和分茶：盖碗/公道杯倾斜方向与目标杯轨迹；每个品茗杯只计一次有效分茶。
- 杯位规范：透视校正后判断一字形、品字形或 `irregular`，不能只输出两个类别。
- 双手奉茶：双手位于茶盘两侧、茶盘离桌并向前移动；鞠躬暂不判定。

## 发布前检查清单

```text
[ ] all_materials.csv 中每个来源路径存在且 session 已确认
[ ] 训练/验证/测试 session 没有交集
[ ] 图片与标签一一对应，类别编号来自同一 classes.txt
[ ] 无孤立 labels.txt、缓存文件或未审核自动标签
[ ] 模糊帧和近重复帧已过滤
[ ] 每个目标类别在 train/val/test 均有足够实例
[ ] 动作正例和困难负例数量平衡
[ ] test 锁定后不再参与训练和阈值调参
```

完成以上检查后，才运行 `publish_front_dataset.py` 生成 YOLO `data.yaml` 并开始 640/batch4 的 GTX 1060 基线训练。长时间训练应放在发布集冻结之后。
